# 꿀뷰 출처 통계 — 인수인계

**현재 버전 v1.5 · 2026-09-29**

꿀뷰 폴더(`Pictures\꿀뷰`)의 사진이 원본 폴더들(`D:\01.메인` + 다른 드라이브의 마이너·일반 폴더) 중 어느 폴더에서 왔는지 세는 크롬 웹앱(PWA).
단일 `index.html`, 빌드 없음. 외부 의존은 Pretendard 폰트(CDN) 하나뿐.

## 파일
`index.html` · `manifest.json` · `sw.js` · `icon-192.png` · `icon-512.png` · `icon-512-maskable.png`
이후 수정은 `index.html` 만 올리면 된다 (sw.js 는 네트워크 우선, 캐시 이름 고정 `kkul-source-shell`).

## 동작
1. **꿀뷰 폴더 훑기** — 이미지 확장자만, 경로·크기·수정시각. 파일은 열지 않는다.
2. **원본 목록** — 원본 폴더마다 따로 훑어 IndexedDB 에 보관. 원본을 추가하면 **그 원본만** 훑는다.
   - **빠른 확인 (v1.4)**: 예전 목록이 있으면 `listDir(..., {prev})` — 폴더의 이름 목록만 읽고, 예전 목록에 있는 파일은
     열지 않고 예전 크기·수정시각을 쓴다. **새 파일만** `getFile()`. 사라진 파일은 목록에 안 나와 저절로 빠진다.
     20분의 대부분이 파일 25만 개를 여는 시간이라 이걸 없앤 것. 한계: 같은 이름으로 덮어쓴 원본은 못 알아챔.
   - **전체 훑기**: 첫 실행, 원본 추가, "원본 전체 다시 훑기" 버튼(`refresh({rescan:true})` → `buildIndex(ids, signal, true)`).
   - 자동 재확인·안내 버튼은 빠른 확인(`refresh({quick:true})`). 결과는 `index.roots[id].lastRun = {quick, took, added, removed}`.
3. **대조** (`resolve`) — 사진마다 `hits`(내용이 같은 원본 경로)와 `npaths`(이름이 같은 원본 경로, hits 가 없을 때만)를 찾아 저장.
   - 크기가 같은 원본만 후보. 이름·크기·수정시각이 모두 같으면 바로 확정, 아니면 지문(크기+앞뒤 256KB SHA-256) 비교
   - 경로는 "묶음이 다를 수 있는 것"만 최대 40개 남긴다 (`thin` — 원본id+첫 폴더 기준)
4. **판정** (`classify`) — **집계할 때마다** hits·npaths 와 지금의 세는 방식으로 계산. 판정 결과는 저장하지 않는다.
   - `ok` 내용 일치가 한 묶음 / `dup` 여러 묶음 / `guess` 이름이 한 묶음에만 / `etc` why = none·many·root
   - 그래서 원본의 세는 방식(폴더별 ↔ 전체 하나로)을 바꿔도 재판정·재스캔 없이 바로 반영된다.

## 원본 폴더와 묶음
- `roots = [{id, h, mode}]` — mode `sub`(바로 아래 폴더별) / `whole`(폴더 전체를 하나로)
- 원본 파일 경로 표기: **`<원본id>/<상대경로>`** (여러 원본을 한 목록에서 다루려고)
- 묶음 열쇠 (`groupOf`): sub → `<id>/<첫 폴더>`, whole → `<id>`. sub 에서 원본 최상위 파일은 null(→ 기타 root)
- 이름표: 원본이 둘 이상이면 폴더명 옆에 원본 이름 딱지, whole 은 "원본이름 [전체]"
- 폴더 겹침 금지 (`overlap`): 같은 폴더·안에 든 폴더·감싸는 폴더는 추가 거부 (같은 사진을 두 번 세게 됨)
- 드라이브 최상위(D:\)는 크롬이 고르게 해 주지 않는다
- **폴더 순위 탭 (v1.5)**: 원본이 둘 이상이면 "전체 / 원본별" 탭(`#rankTabs`). 고른 탭은 `settings.rankTab` 에 저장.
  원본 탭에서는 그 원본의 묶음만, 이름표 없이(`gHTML(g,true)`), 비율은 **그 원본 장수(+다른 원본과 중복)** 기준.
  중복 행은 "다른 원본과 중복"(그 원본 묶음이 들어간 dup), 기타 행은 전체 탭에만. 화면 필터라 재판정·재스캔 없음.

## 저장 (IndexedDB `kkul-source` / store `kv`)
| 키 | 내용 |
|---|---|
| `hT` | 꿀뷰 폴더 핸들 |
| `roots` | 원본 폴더들 `[{id, h, mode}]` |
| `index` | `{gen, roots:{id:{builtAt, name, files:[[상대경로,크기,수정시각]], stat}}}` — 원본 하나 훑을 때마다 저장 |
| `fpO` | 원본 지문 캐시 `"<id>/경로\|크기\|수정시각" → 지문` |
| `results` | `"꿀뷰경로\|크기\|수정시각" → {hits, npaths, gen, sig, lv, seen, name}` |
| `colors` | 묶음 열쇠 → 색 칸 번호 |
| `settings` `last` | 자동 재스캔 여부 / 마지막 갱신 |

## 증분 갱신 규칙 — 건드릴 때 주의
- 재사용 조건: `lv===LOGIC(3)` && `sig`(원본 id 목록)가 같음 && (hits 가 있음 || `gen` 이 같음).
  원본을 추가·제거하면 sig 가 바뀌어 전부 재판정하지만 **원본은 다시 안 훑는다**(지문 캐시 덕에 빠름).
- `seen` = 그 사진을 처음 본 **갱신 시작 시각**. hits·npaths 가 모두 없고 `seen > 가장 오래된 원본 builtAt` 이면
  "원본에 새 폴더가 생겼을 수 있다"로 보고 자동 재스캔(전체 원본, 갱신 한 번에 최대 1회).
- 중단하면 거기까지 판정한 것·다 훑은 원본은 저장된다.

## v1.2 → v1.3 이전 (`migrate`) ★
- `hO` → `roots[{id:"r1"}]`, `index` 는 `index.roots.r1` 로, `fpO`·`colors` 열쇠에 `r1/` 을 붙인다. **원본을 다시 안 훑는다.**
- 예전 `results` 는 버리지 말고 모양만 바꿔 옮긴다 (`tops` → `r1/<폴더>/_` 경로). **`seen` 을 지켜야 한다.**
  처음엔 비웠다가 테스트에서 걸렸다 — seen 이 전부 "지금"이 되어 첫 갱신에 기타 전부가 "새 사진"으로 잡히고
  원본 전체 자동 재스캔(20분+)이 돌 뻔했다. `lv` 는 예전 값이라 첫 갱신 때 새 규칙으로 재판정된다.

## 함정
- 폴더 권한은 **클릭 직후에만** 물을 수 있다. 두 폴더를 연달아 물을 때 두 번째가 실패하면
  "한 번 더 눌러 달라"는 안내가 나온다. 권한 창에서 "방문할 때마다 허용"을 고르면 다시 안 묻는다.
- 테스트 환경(리눅스 헤드리스 크로미움)의 OPFS 는 **한글 폴더 이름을 제대로 못 다룬다**
  (폴더가 사라지고 안의 파일이 위로 올라온다). 테스트용 가짜 폴더는 영문으로 만들 것. 실제 윈도에서는 문제 없음.
- 테스트 창구: `window.KS` = `{S, refresh, render, put, get, classify, setMode, removeRoot, useHandles(꿀뷰, ...원본들), addHandle(원본, mode)}`
  (`useHandles` 로 만든 원본 id 는 `t0`, `t1` …)
